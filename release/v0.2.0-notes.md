# v0.2.0

**Babel became more truthful about what it verified, what nobody attested, and
what carries forward.**

No artifact format changed. No run changes verdict. What changed is what the
tool is willing to claim, and how much of that claim is visible on the first
line.

Every change came from running 0.1.0 against a real handoff that had been
carried across sixty-five sessions, and reading what it printed.

## The change worth reading about

0.1.0 printed this for an artifact whose producer had declared no authority at
all:

```
  authority agreement ... verified   2 encodings agree
```

Those two encodings were the verifier's own, agreeing with itself. `seal` had
always refused to write its own authority entries into an artifact, on the
grounds that it would be *marking its own homework* — and the verifier was
doing exactly that, in its status column, in the same word it used for a layer
an independent encoder had corroborated.

It is the same condition `external truth` had always reported honestly, so it
now uses the same word.

## What the output looks like now

```console
$ babelci carry examples/clean-handoff.json --checkpoint cp-4412-02 --consumer agent-c | babelci seal - > next.json
$ babelci verify next.json --expect examples/expect.json

PASS  next.json
      6 verified · 2 not established
  structure ............. verified   contract 0.1, 4 objects
  identity .............. verified   agent-b -> agent-c
  checkpoint ............ verified   cp-4412-02
  provenance ............ verified   4 objects to repo@a1b2c3d4
  retained constraints .. verified   2 MUST, 1 SHOULD
  conflicts ............. verified   none, 1 open
  authority agreement ... not established
  external truth ........ not established
```

Three things in that report are new. The census on the second line counts what
was assessed and what was not. `conflicts` says how many issues were declared
open rather than a bare `none`. And the authority layer says nobody independent
checked, because the successor's producer has not computed a commitment yet —
`carry` deliberately did not inherit the predecessor's.

An artifact whose producer declares nothing open now reads:

```
  conflicts ............. verified   none, 0 open (unattested)
```

## What ships

- **`authority agreement` reports `not established`** when the producer
  declared no authority. `AUTHORITY_SINGLE_ENCODING` keeps its `note` severity
  and its meaning.
- **A coverage census** under the verdict. Counts side by side, never combined
  into a figure — collapsing them is how a verifier becomes a rubber stamp,
  which is why the layers are not averaged either. After a structural exit it
  reports the layers that never ran.
- **`SILENCE_UNATTESTED`** (`note`). The contract has always said silence in
  `unresolved` claims nothing is open; nothing checked that claim unless an
  expectation required an issue to survive. Now the report says so.
- **`PROVENANCE_ROOT_MISMATCH`.** The expectation's `authority_root` is checked
  against the artifact's. That key shipped in `examples/expect.json` in 0.1.0
  and the verifier never read it.
- **`babelci carry`.** Drafts the successor of a handoff so continuity is the
  default rather than something retyped at the end of a session. It withholds
  `authorities`, `external_receipt` and `summary`, because carrying any of them
  would assert something the successor's producer never claimed.

Still zero runtime dependencies, no network, no telemetry.

## Migration

Nothing to do. No artifact needs changing and no configuration needs adding.

- **Exit codes are unchanged for every artifact that exists.** `not established`
  has never been a failure, and `SILENCE_UNATTESTED` is `note` severity.
  `PROVENANCE_ROOT_MISMATCH` is the only new check that can fail a run, and only
  when an expectation names an `authority_root`.
- **Output changed for artifacts declaring no `authorities`**: one status line,
  plus the census. If you parse Babel's output, parse `--json` —
  `layers[].status` has carried this since 0.1.0.
- **To adopt `authority_root` enforcement**, add the key to your expectation
  file. The artifact must already ground its facts in that root; if your
  producer writes a placeholder, enforcing a real root fails until the producer
  is updated too.

## Compatibility

Contract version is unchanged at `0.1`. No field added or removed, no digest
recipe or canonical encoding changed, no finding code changed meaning, no diff
rule changed verdict. Artifacts sealed by 0.1.0 verify identically under 0.2.0,
and artifacts produced by 0.2.0 verify identically under 0.1.0.

`docs/COMPATIBILITY.md` now separates contract compatibility from report
compatibility, because this release is a change to what the tool prints rather
than to what an artifact is, and the previous wording did not draw that line.

## Limitations

[`docs/LIMITS.md`](../docs/LIMITS.md) is unchanged, which is the point: nothing
here moved the claim boundary. Babel still does not determine whether text is
true and still does not detect hallucination. Specific to this release:

- A `not established` authority layer says nobody independent checked. It does
  not say the artifact is wrong — and a `verified` one still only means two
  encoders agreed about a world that may never have existed.
- `SILENCE_UNATTESTED` reports that a claim went unchecked. It cannot tell you
  whether anything is actually open.
- `PROVENANCE_ROOT_MISMATCH` compares two strings. A match establishes that the
  artifact names the expected root, not that the root is real or trustworthy.
- `carry` copies what a predecessor asserted. A wrong predecessor produces a
  faithfully wrong successor; `babelci diff` against a *correct* predecessor
  remains the check for that.
- The census counts layers. It is not a score.

## Not in this release

- **Claim objects with confidence rungs** — designed, not built. The reporting
  changes above already state an artifact's epistemic position without new
  vocabulary or anything for a producer to fill in. Deferred until something
  needs to record a claim the existing objects and constraints cannot carry.
- **A diff rule for unchanged summaries** — dropped. `carry` withholds the
  summary, which prevents stale prose being re-committed rather than detecting
  it afterwards.
