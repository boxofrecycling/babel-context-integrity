Babel Context Integrity

Verify what survives when one AI agent hands work to the next.

Git checks your code. Babel checks what your next agent thinks happened.

Your agent runs out of context and hands off. The successor inherits a summary — and the constraint that said don't drop the legacy table yet is no longer in it. Nothing notices.

Exit code 1. Your CI check goes red — before a human reads a summary that no longer matches the code.

The part most tools skip

Look at the last line. External truth: not established.

Everything above it is internal consistency. Babel recomputed the commitments, walked the provenance graph, and encoded the artifact twice with two independent encoders that agreed. That is a real result. It is not the same as the story being true.

Here is a handoff from an agent that scanned the wrong branch. Every fact in it is wrong. Every internal check passes:

$ babelci verify examples/common-mode-handoff.json

  checkpoint ............ verified
  provenance ............ verified

  conflicts ............. verified

    repository working tree at repo@a1b2c3d4 rejected this world:
    auth.provider is okta-oidc in the tree, not auth0-oidc;
    legacy.sessions counted 1843 rows, not 12

Two encoders sharing no code agree completely — because they are both reading the same false artifact. Only a receipt issued outside the artifact catches it, and that receipt is now the thing you have to trust.

Agreement is not truth. Babel is built to show you where one stops and the other begins, instead of collapsing them into a green tick.

Install

$ pip install babel-context-integrity
$ babelci demo

Python 3.10+. Zero runtime dependencies. Zero network access. No telemetry. Enforced by a test that parses every module's imports, and a CI job that runs the whole suite with outbound traffic firewalled off.

Runs in CI

A GitHub Action wrapping the same CLI. Failures block the check. No cloud account, no token, no service.

Runs offline

Works under --network=none. Nothing is sent anywhere, because there is no code in the package that could send it.

What it checks

layerestablishes
structurethe artifact matches the declared contract version
identityit concerns the work you expected
checkpointthe commitment recomputes from the state it carries
provenanceevery assertion reaches the authority root
constraintswhat had to survive, survived unmodified
conflictsno unresolved contradiction about one object
authoritiestwo independent encoders read it the same way
external truthsomething outside the artifact accepted it

Reported separately, never averaged. Each layer ends in verified, FAILED, or not established — because a check that could not run is not a check that passed.

The lab

babelci lab runs 15 failure classes, each generated from one clean handoff by one named mutation — so the difference between pass and fail is always a single edit you can read.

  • constraint-dropped — a MUST constraint stops being carried
  • constraint-softened — it keeps its id and changes meaning
  • decision-reversed — verify can't see it; diff refuses it
  • summary-drift — the prose no longer matches the state
  • provenance-break — a fact loses its chain to the repository
  • alias-collapse — compaction makes two names mean one thing
  • authority-disagreement — two encoders read it differently
  • compression-loss — compaction drops a required object
  • common-mode — everything agrees, everything is wrong

Integrity machinery costs 7,064 of 21,848 bits (32.3%) of the example artifact. Measured by the lab, not estimated.

Limits

Read these before believing anything above.

  • Babel does not check whether text is true. It checks whether a structured artifact satisfies a declared contract.
  • It does not detect hallucination. A hallucinated fact with a plausible provenance label and a correct commitment verifies.
  • Encoder agreement is not truth. That is the common-mode case — a limitation, not a feature.
  • The external receipt is a trust root, not a solution. Babel moves trust somewhere you can name and audit. It does not remove it.
  • No language model was involved in this research. The lab agents are deterministic fixtures. A real-model evaluation is designed and has not been run.
  • Structured agent handoffs are not new. The related-work review names CLAN and ~20 other projects before describing what differs here.

Hosted beta

The CLI, the contract, the lab and the CI action are open source under Apache-2.0 and stay that way. What a local check cannot do is answer "when did constraint C1 stop being carried, and in which PR?" — that needs history across runs and repositories.

Handoff history, signed team receipts, policy as code and cross-repository visibility are not built yet. If that is useful to you, say so and it gets prioritised.
